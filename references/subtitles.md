# 字幕是怎么来的

字幕不是外挂的，是**从配音时间轴推出来的**——所以它天生和旁白严丝合缝，不需要手打时间码。

```
segments[i].sub ──┐
                  ├─ tts ─▶ work/timeline.json（每段 start/dur/end）─▶ subs ─▶ work/subs.ass（烧进画面）
segments[i].tts ──┘                                                          work/subs.srt（外挂投稿）
```

## 一、时间：一条字幕 = 一段旁白

`tts` 把每段合成后量出真实时长，写进 `work/timeline.json`：

```json
{"i": 3, "start": 11.70, "dur": 6.29, "end": 17.99, "sub": "左边一排背景，点一下就套上……"}
```

`subs` 按 `start → start + dur + 0.30` 出字幕：**尾部多留 0.30s**，避免话音刚落字就消失（那是"字幕抢拍"的典型观感）。最后一条再和总长取 `min`，不会溢出到片尾之外。

所以改文案不用手改时间——`script` 重新灌文案、`tts` 重跑，时间轴自动重算。

## 二、折行：只断在标点后

libass 默认会在任意字符处硬断，中文长句会被切成"左边一排背 / 景，点一下就套 / 上"这种。渲染器自己折：

1. 一行 ≤ 20 字（约 4 字余量）就不折；
2. 超了就在**离中点最近的标点后面**断，插 `\N` 换行；
3. 标点优先级：**`，。：；？！`（语义停顿）优先**，`、`（顿号）只在没有前者时才用。

第 3 条是踩出来的：早先一视同仁地找标点，`支持 txt、epub、html 三种格式` 被拆成 `支持 txt、` / `epub、html...`，把并列项硬生生劈开。

两行都放不下时不要硬折第三行——**删字**，比挤三行清楚。

## 三、口播 ≠ 字幕

| 项 | 口播 `tts` | 字幕 `sub` |
|---|---|---|
| 气声标记 `[笑]` `[轻笑]` `[叹气]` | 保留，合成器认 | **去掉**（写进去会原样显示出来） |
| 数字 | 「二百五十五」念得顺 | `255` 一眼能读 |
| 专有名词 | 可以连读 | 用「」或破折号隔开，防歧义 |
| 标点 | 影响停顿节奏，该逗就逗 | 影响折行，宁可多一点标点 |

`rec2video.py script` 会自动按这个规则生成 `sub`（去掉方括号事件），所以 `narration.txt` 里直接写 `[笑] 开场白` 就行，字幕里不会出现 `[笑]`。

## 四、样式与位置

```json
"subtitle": {"font": "Microsoft YaHei", "size": 46, "margin_v": 46}
```

- **字号 46**（1920×1080 基准）：1080p 下约 2.4% 行高，手机屏也读得清；竖屏或 4:3 成片按比例放大。
- **描边 3.4 + 阴影 1.8**：画面里既有深色也有白色区域，纯白字不加描边会糊在亮处。
- **`margin_v` 是从画面底边往上留的距离**，不是"离画框的距离"。画面嵌在画框里（默认 1560×878 @ y=56，下沿到 934），底部只剩 146px；两行字幕约 94px + 描边，所以 `margin_v` 只能给到 46，再大就顶到画框上了。
- 想给字幕更多空间：压 `video.frame.h`（比如 878 → 820），而不是把字幕往上推。

## 五、两套输出，各有用途

| 文件 | 用途 |
|---|---|
| `work/subs.ass` | 渲染时 `subtitles=` 烧进画面。**每次 render 都重新生成**，改文案/字号立刻生效，不做缓存（缓存过一次，改了文案成片还是旧的） |
| `work/subs.srt` | 外挂字幕，投 B 站/YouTube 时上传。烧录版字太小或平台要压 CC 时用它 |

单独重出字幕（不用等整片渲染）：

```bash
python scripts/rec2video.py subs demo/project.json
```

## 六、片头片尾标版

`caption` 是另一套样式（顶部小字，`Bar`，字号 ×0.82，无描边）：

```json
"caption": {"start": "Recordly ｜ 开源录屏 + 剪辑", "end": "github.com/webadderallorg/Recordly ｜ ★ 36.9k",
            "start_at": 0.3, "start_until": 4.4, "end_at": 71.3}
```

- 片头 0.3–4.4s：项目名 + 一句话定位；
- 片尾 `end_at` 到结束：仓库地址 + star 数（`new --repo` 会自动填，`cut` 会按总长重算 `end_at`）；
- **数字口径必须和封面、标题、简介一致**，star 数现查，别抄参考视频。

## 七、检查清单

1. 有字幕的两行吗？两行有没有压到画框下沿（看 `check` 的 `gap_bottom`）。
2. `[笑]` 有没有漏进画面？漏了就是 `sub` 里没清干净。
3. 数字是不是阿拉伯数字、和口播读法一致（`三万多` vs `36.9k` 别混用）。
4. 最后一条字幕有没有在片尾标版出来前消失。
5. 中文字体存不存在：不存在的字体会整段变方块，`ffmpeg` 不报错。
