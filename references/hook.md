# 开场三秒：复述标题 → 点名 → 砸数字

一句话：**观众是被标题骗进来的，前三秒只干一件事——让他确认「我点对了」，并且立刻知道这是个什么东西。**

这一段单独讲，因为它和第 3 节的其它规则冲突时，先赢的是这一段。

## 〇、借的是广告的手法，不是把片子做成广告

这条片子是项目介绍：最终目的是让人去拉仓库、去用，不是让人下单。**但开头这套打法就是广告的**——标题、封面大字、口播首句、简介首句四处说的是同一句话。**这不是文案偷懒，是短视频唯一的记忆机制**：信息流只给你 1.5 秒，一个卖点说一次等于没说，得在四个入口砸四遍，砸到观众心里冒出「这玩意儿好像最近老刷到」的熟悉感——熟悉感本身就等于可信度。

手法借了，就得借全套，广告的三件套：**重复 + 浮夸 + 具体**。

| 只做到 | 结果 |
|---|---|
| 重复 | 祥林嫂。同一句平淡的话念四遍，观众只觉得你在硬推 |
| 重复 + 浮夸 | 吹牛不打草稿。观众第一反应是"又一个营销号"，反而扣分 |
| 重复 + 具体 | 说明书。信息对了，但没人愿意看 |
| **三个都要** | 观众记住了那句话，并且相信它 |

浮夸的形态是**给事实装放大器，不是造事实**：

| 原事实 | 可以说成（浮夸） | 不许说成（造假） |
|---|---|---|
| 支持 14 个音源 | 14 个源，狠活；一个框把 14 家全端了 | 全网所有平台通吃 |
| 3.9k stars | 斩获 3.9k Stars | 破万 Star、万人 star |
| 有抓包 / MITM / 指纹伪装 | 抓包、改包、指纹伪装，全塞进一个客户端 | 能破解任意 App 的加密 |
| 本地跑、不联网 | 数据一步都没出过你这台机器 | 绝对安全、永不泄露 |

左边是能对着仓库验的，中间是情绪和措辞，右边是话术越界。**越界的代价不是被骂，是被人截图挂出来。**

浮夸的剂量也在这条线上：**重复止于四个入口**。第 2 段往后一律老实讲功能，再出现「神器」「狠活」「离谱」就是复读机——观众能忍开头吹，忍不了全程吹。


## 一、顺序：先定标题，再写第一句

标题在 `cover` 和发布页才定，很多人就最后才写，于是第一段只能靠"痛点铺垫"。正确顺序是：

1. 先把标题定死（第 7 节句式，或者你自己那句最能打的）。
2. **把标题原文写进 `project.json` 的 `title`**——标题只活在对话里，之后没人验得了首句（`script --title "…"` 一步写进去）。
3. 把标题**翻译成口语**当第一段，字数别超 30。
4. 正文再按画面往下写。

写第一段时手上必须有标题原句。没有就先别写——`hook` 会直接判「没有 title」。

### 反例 / 正例（同一素材，go-music-dl）

发布标题（第 7 节狠活体）：

```
好家伙！Github又出狠活神器！14 个音乐源塞进一个搜索框，斩获 6.5k Stars，网易云、QQ、酷狗、酷我全支持
```

```
✗ [笑] 想下一首歌，得来回切四五个网站，这事以前只能忍着。
```

第 1 秒给的是观众早就知道的事。标题说"14 个音乐源""神器"，画面里也是，但旁白一个字都没提。观众不知道这视频要给他什么，走。

```
✓ [笑] 14 个音乐源，就塞进一个搜索框——神器 go-music-dl。
```

同一句话里给了：标题的核心数字（14 个音乐源）、标题的核心画面（塞进一个搜索框）、标题的情绪词（神器）、名字（go-music-dl）。三秒内信息闭合。

## 二、复述 ≠ 朗诵

"重复标题"是让第一句**承接标题的信息和情绪**，不是把标题连标点念一遍。那条 60 字的标题念出来要 15 秒，观众早跑了。

搬运规则：

| 标题里的 | 口播怎么处理 |
|---|---|
| 数字（14 个音乐源、6.5k Stars） | **原词原数搬**，一个字不改 |
| 核心名词（一个搜索框） | 搬，可以换个更短的说法但别换成别的概念 |
| 情绪词（神器 / 狠活 / 天花板） | 留一个，放在破折号后面当重音落点；`王炸`/`炸裂` 只在标题里出现，口播念出来是噪音 |
| 平台前缀（Github / B站） | 可以不搬，口播说"Github"没人有画面 |
| 套话（这块最高的山来了 / 斩获） | 不搬，留给标题党 |

一句话检验：**把第一句和标题并排放，能不能一眼看出它们是同一件事。** 看不出就是没复述；逐字一样就是朗诵，也不行。

## 三、三秒里的四件事

| 时间 | 要给 | 要求 |
|---|---|---|
| 0–1s | 标题里的核心词 | **原文照搬，不许换词换数**。标题写"14 个音乐源"，口播就别说"十几个平台" |
| 1–2s | 名字 + 一句定性 | 项目名/软件名 + 它是干什么的、谁写的、开源不开源 |
| 2–3s | 一个数字或一个反常识 | 源数量、体积、耗时、免费、本地跑、不用登录——挑最狠的那个 |
| 全程 | 情绪 | 语气和节奏，不是感叹号 |

**为什么要照搬标题**：观众在信息流里只扫到标题那半句，手指已经点下来了。第一句接上原词，大脑立刻确认"对，就是这个"，留存就成立了。换成同义词，等于让他重新判断一次。

**为什么数字必须靠前**：数字是唯一能在 1 秒内建立可信度的东西。"很多源"是形容词，"14 个源"是事实。

## 四、"甲亢"的边界：浮夸在语气，不在音量

上一节说的「浮夸」很容易被理解成喊。不是。要的是**信息密度 + 短句节奏**，不是音量和感叹号。喊得越响、信息越少，跳出越快——两个人都在喊「神器」，一个后面跟着 14 个源的名字，一个只会喊神器，留人的是前者。

能用的：

- 短句连砸：`一个框。十四家。全搜。`
- 口语转折起头：`真就一个框。` / `离谱的是——` / `我一开始也不信。`
- 具体到荒谬的量词：`十四家` > `很多家`；`三秒` > `很快`
- 第一人称真实反应：`我翻了两遍才确认它真没让我登录。`

不能用的（写文案时搜一遍这些词，出现就删）：

- 空感叹：`太强了` `绝了` `无敌` `炸裂` `王炸` —— 观众听过一万遍，等于噪音
- 无信息的形容词堆：`超级强大、极其好用`
- 没支撑的假惊讶：`万万没想到` `惊呆了`（后面接不出具体反差，就是套话）
- 贬低同行：`XX 可以卸载了`（招举报，且显得心虚）

一句话判据：**把这句话里的情绪词删掉，如果信息一点没少，那这个词就是废的。**

## 五、七个可以直接套的模板

| 模板 | 句式 | 适合 |
|---|---|---|
| 神器体复述 | `<数字>个<对象>，就<塞进/干完>一个<东西>——神器 <项目名>。` | 标题是狠活体的项目，最贴标题 |
| 通用复述 | `<标题量词>，一个<东西>全搞定——<项目名>。` | 标题是白描体的项目 |
| 质疑 | `<大家都在忍的麻烦>还得<操作>？<项目名>把这个框直接干掉了。` | 工具替代类 |
| 数字 | `<数字>个<单位>，<数字>秒<完成>，开源，本地跑——<项目名>。` | 参数党的项目 |
| 反差 | `这玩意儿只有<很小>，能干<很重>的事。` | 小体积/单文件/无依赖 |
| 现场 | `别眨眼，<动作>这一下——<结果>。` | 有强视觉反馈的操作，**必须和画面严格同步** |
| 直给 | `<项目名>，<一句话是什么>，<最狠的能力>。` | 名字本身就是卖点 |

套完都要过第 5 节的自检。模板只解决句式，不解决有没有料。

## 六、三条纪律

1. **第一段配的画面必须是"最完整的全貌"**。不能落在加载中、弹窗、滚动条半路。观众第一眼看到半截界面，会以为视频卡住，直接划走。
2. **开场句不许和画面对打**（同 `lessons.md` 第六节）。画面已经是完整漂亮的界面，旁白却说"打开还是乱糟糟的"，就是自己拆自己。
3. **情绪只放头和尾**。第一段冲，最后一段（求 star）收，中间老老实实讲功能。全程甲亢 = 没有甲亢，观众会疲劳。

## 七、机器校验：先跑 `hook`

"我觉得复述了"不算数。标题原文写进 `project.json` 的 `title`，然后：

```bash
python scripts/rec2video.py hook <工程>/project.json
```

`scripts/hookcheck.py` 不联网、不读视频，只比标题和 `segments[0]`，判四条：

| 项 | 判据 | 不过怎么办 |
|---|---|---|
| 标题落盘 | `title` 非空 | `script <工程> <txt> --title "好家伙！…"` |
| 项目名 | 首句含仓库名/工程名（大小写、`-`/空格不敏感） | 第 2 秒前把名字念出来 |
| 数字 | 标题里的数字至少落一个进首句 | 把最狠那个数字搬进前三秒 |
| 字面重合 | 与标题的 3-gram 覆盖 ≥ 20%（35% 以上算舒服） | 低于 20% 基本是另起一句，重写 |

比对时会先挖掉 `[笑]` 这类气声标记，以及 `好家伙 / 神器 / 狠活 / 斩获 / Github / Stars` 这些套话——复述本来就允许丢掉它们，不该因此判不及格。

`script` 和 `check` 都会自动跑这一项；`hook` 判 ✗ 时退出码是 2，别当噪音忽略。

## 八、交付前自检（机器判不了的）

写完第一段，遮住标题念一遍：

- [ ] 只听这一句，能不能猜出标题大概写了什么
- [ ] 和发布标题并排看，是不是同一件事（看不出 → 没复述；逐字一样 → 朗诵，都得重写）
- [ ] 项目名在第几秒出现（> 2s 就往前挪）
- [ ] 有没有一个具体数字
- [ ] 有没有空感叹词（有就删，删完读一遍看信息少没少）
- [ ] 第 3 秒结束时，一个完全没听过这项目的人，知不知道它是干什么的
- [ ] 封面大字、简介首句，和这句是不是同一个口径（核心数字 + 核心名词别各说各的）
- [ ] 这句算不算浮夸得起来：删掉情绪词之后，剩下的信息还够不够硬（不够说明需要的是加事实，不是加形容词）
- [ ] 每一处浮夸背后有没有一个能对着仓库验的事实（没有 → 那是造假，删掉重写）

九条里有任何一条不过，就重写第一段，别往下写第二段。
