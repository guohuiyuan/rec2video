# 开场三秒：第一句就是标题 → 点名 → 砸数字

一句话：**观众是被标题骗进来的，前三秒只干一件事——让他确认「我点对了」，并且立刻知道这是个什么东西。**

这一段单独讲，因为它和第 3 节的其它规则冲突时，先赢的是这一段。

## 〇、借的是广告的手法，不是把片子做成广告

这条片子是项目介绍：最终目的是让人去拉仓库、去用，不是让人下单。**但开头这套打法就是广告的**——标题、封面大字、口播首句、简介首句四处说的是同一句话。**这不是文案偷懒，是短视频唯一的记忆机制**：信息流只给你 1.5 秒，一个卖点说一次等于没说，得在四个入口砸四遍，砸到观众心里冒出「这玩意儿好像最近老刷到」的熟悉感——熟悉感本身就等于可信度。

手法借了，就得借全套，广告的三件套：**重复 + 浮夸 + 具体**。

| 只做到 | 结果 |
|---|---|
| 重复 | 祥林嫂。同一句平淡的话念四遍，观众只觉得你在硬推 |
| 重复 + 浮夸 | 吹牛不打草稿。观众第一反应是"又一个营销号"，反而扣分 |
| 重复 + 具体 | 说明书。信息对了，但没人愿意看 |
| **三个都要** | 观众记住了那句话，并且相信它 |

浮夸的形态是**给事实装放大器，不是造事实**：

| 原事实 | 可以说成（浮夸） | 不许说成（造假） |
|---|---|---|
| 支持 14 个音源 | 14 个源，狠活；一个框把 14 家全端了 | 全网所有平台通吃 |
| 3.9k stars | 斩获 3.9k Stars | 破万 Star、万人 star |
| 有抓包 / MITM / 指纹伪装 | 抓包、改包、指纹伪装，全塞进一个客户端 | 能破解任意 App 的加密 |
| 本地跑、不联网 | 数据一步都没出过你这台机器 | 绝对安全、永不泄露 |

左边是能对着仓库验的，中间是情绪和措辞，右边是话术越界。**越界的代价不是被骂，是被人截图挂出来。**

浮夸的剂量也在这条线上：**重复止于四个入口**。第 2 段往后一律老实讲功能，再出现「神器」「狠活」「离谱」就是复读机——观众能忍开头吹，忍不了全程吹。


## 一、顺序：先定标题，再把标题抄成第一句

标题在 `cover` 和发布页才定，很多人就最后才写，于是第一段只能靠"痛点铺垫"。正确顺序是：

1. 先把标题定死（第 7 节句式，或者你自己那句最能打的）。
2. **把标题原文写进 `project.json` 的 `title`**——标题只活在对话里，之后没人验得了首句（`script --title "…"` 一步写进去）。
3. **把标题原句整句抄进 `narration.txt` 第 1 行**，句首再加一个 `[笑]`。不翻译、不压缩、不调语序。
4. 正文再按画面往下写。

写第一段时手上必须有标题原句。没有就先别写——`hook` 会直接判「没有 title」。

### 反例 / 正例（同一素材，花笺 floral-notepaper）

发布标题（第 7 节狠活体）：

```
GitHub 又出狠活！一个快捷键就冒出一张便签，Markdown 双栏实时预览，斩获 5.6k Stars——花笺
```

```
✗ [笑] 想记个东西，总得先切窗口、找应用、再点新建。
```

第 1 秒给的是观众早就知道的事。标题说"快捷键""便签"，画面里也是，但旁白一个字都没提。观众不知道这视频要给他什么，走。

```
✗ [笑] 一个快捷键，桌面冒出一张便签——花笺 Floral Notepaper，5.6k 星。
```

这是"复述版"：顺、短、听得懂，但丢了「GitHub」（信任锚）、「Markdown 双栏实时预览」（最硬的卖点）、「斩获」（情绪落点），与标题的字面重合只有 **33%**。观众在推荐流里扫到的那半句，进视频第一秒一个词都没接上，等于把标题买来的流量又退回去。

```
✓ [笑] GitHub 又出狠活！一个快捷键就冒出一张便签，Markdown 双栏实时预览，斩获 5.6k Stars——花笺
```

重合 100%。观众听到的第一个词，就是他刚才扫到的第一个词。

## 二、照念，不是复述

上一版这一节写的是"复述 ≠ 朗诵：60 字的标题念完 15 秒，所以要压缩"。规范定成这样，执行就一定漂——改写的成本是零，"稍微顺一点"的诱惑一直在，每个环节顺手压掉几个词，最后和标题就没关系了。实测漂过两次（`SKILL.md` 3.1、`lessons.md` 第十八节）。

现在只有一条：**第一句 = 标题原句，只许在句首加一个 `[笑]`。**

| 情况 | 怎么做 |
|---|---|
| 标题里有数字（5.6k Stars、14 个源） | 一个都不许漏；读法可以调（"5.6k 星"仍算数），数字本身不许改 |
| 标题里有情绪词（狠活 / 神器 / 斩获） | 照念。它们在标题里就是为了抓眼，念出来确实有点响——那是标题本身响，删掉等于删标题 |
| 标题里有平台前缀（GitHub / B站） | 照念。它是信息流里的信任锚，省掉就从"一个真项目又出狠活了"变成"某个不知名工具" |
| 标题太长（> 40 字 / 念完 > 8 秒） | 回去改标题：删句头套话、砍形容词、并短句。**不在首句里删** |
| 某个词 TTS 一定念错 | 改标题里的那个词（Tauri 念成"套利奥" → 标题写"Rust + React"），首句跟着一起改 |
| 标题带 `[笑]` 这类标记 | 写在首句最前面，`sub` 里自动去掉，不计入字面 |

一句话检验：**把首句和标题并排放，能不能逐字对上。** 对不上就是改了，改了就判 ✗。

## 三、三秒里的四件事

| 时间 | 要给 | 要求 |
|---|---|---|
| 0–1s | 标题里的核心词 | **原文照搬，不许换词换数**。标题写"14 个音乐源"，口播就别说"十几个平台" |
| 1–2s | 名字 + 一句定性 | 项目名/软件名 + 它是干什么的、谁写的、开源不开源 |
| 2–3s | 一个数字或一个反常识 | 源数量、体积、耗时、免费、本地跑、不用登录——挑最狠的那个 |
| 全程 | 情绪 | 语气和节奏，不是感叹号 |

**为什么要照搬标题**：观众在信息流里只扫到标题那半句，手指已经点下来了。第一句接上原词，大脑立刻确认"对，就是这个"，留存就成立了。换成同义词，等于让他重新判断一次。

**为什么数字必须靠前**：数字是唯一能在 1 秒内建立可信度的东西。"很多源"是形容词，"14 个源"是事实。

## 四、"甲亢"的边界：浮夸在语气，不在音量

上一节说的「浮夸」很容易被理解成喊。不是。要的是**信息密度 + 短句节奏**，不是音量和感叹号。喊得越响、信息越少，跳出越快——两个人都在喊「神器」，一个后面跟着 14 个源的名字，一个只会喊神器，留人的是前者。

能用的：

- 短句连砸：`一个框。十四家。全搜。`
- 口语转折起头：`真就一个框。` / `离谱的是——` / `我一开始也不信。`
- 具体到荒谬的量词：`十四家` > `很多家`；`三秒` > `很快`
- 第一人称真实反应：`我翻了两遍才确认它真没让我登录。`

不能用的（写文案时搜一遍这些词，出现就删）：

- 空感叹：`太强了` `绝了` `无敌` `炸裂` `王炸` —— 观众听过一万遍，等于噪音
- 无信息的形容词堆：`超级强大、极其好用`
- 没支撑的假惊讶：`万万没想到` `惊呆了`（后面接不出具体反差，就是套话）
- 贬低同行：`XX 可以卸载了`（招举报，且显得心虚）

一句话判据：**把这句话里的情绪词删掉，如果信息一点没少，那这个词就是废的。**

## 五、七个可以直接套的**标题**模板

这一节以前叫"开场句模板"——因为第一句要另写。现在第一句就是标题，模板的落点前移一层：**模板只用来写标题，写完照抄进第一段。**

| 模板 | 句式 | 适合 |
|---|---|---|
| 狠活体 | `<情绪词>！Github又出狠活神器！<数字>个<对象><塞进/干完>一个<东西>，斩获 <X.X>k Stars，<能力>全支持` | 默认首选 |
| 神器体 | `<数字>个<对象>，就<塞进/干完>一个<东西>——神器 <项目名>` | 能力清单型项目 |
| 白描体 | `<量词>，<动词> <数字>个<对象>` | 平台限流夸张词 / 严肃工具 |
| 数字 | `<数字>个<单位>，<数字>秒<完成>，开源，本地跑——<项目名>` | 参数党 |
| 反差 | `这玩意儿只有<很小>，能干<很重>的事` | 小体积 / 单文件 |
| 现场 | `别眨眼，<动作>这一下——<结果>` | 有强视觉反馈（要能和画面同步） |
| 直给 | `<项目名>，<一句话是什么>，<最狠的能力>` | 名字本身就是卖点 |

两条硬约束，都是照念带来的：

1. **念得完**：≤ 40 字，约 8 秒。超过就砍句头套话，别指望首句去压缩。
2. **前 15 字里有硬信息**（数字或反常识）。标题的语序就是口播的语序——数字埋在最后，前三秒就只剩套话。

套完都要过第八节的自检。模板只解决句式，不解决有没有料。

## 六、三条纪律

1. **第一段配的画面必须是"最完整的全貌"**。不能落在加载中、弹窗、滚动条半路。观众第一眼看到半截界面，会以为视频卡住，直接划走。
2. **开场句不许和画面对打**（同 `lessons.md` 第六节）。画面已经是完整漂亮的界面，旁白却说"打开还是乱糟糟的"，就是自己拆自己。
3. **情绪只放头和尾**。第一段冲，最后一段（求 star）收，中间老老实实讲功能。全程甲亢 = 没有甲亢，观众会疲劳。

## 七、机器校验：先跑 `hook`

"我觉得照念了"不算数。标题原文写进 `project.json` 的 `title`，然后：

```bash
python scripts/rec2video.py hook <工程>/project.json
```

`scripts/hookcheck.py` 不联网、不读视频，只比标题和 `segments[0]`，判五条：

| 项 | 判据 | 不过怎么办 |
|---|---|---|
| 标题落盘 | `title` 非空 | `script <工程> <txt> --title "…"` |
| **就是标题** | 与标题的 LCS 字面重合 ≥ 85% | 低于 85% 把标题整句抄进去；55%–85% 且首句是标题的连续片段 → 判"删了句头"，只给 `!` |
| 数字 | 标题里每个数字都要在首句 | 漏了就是改写版，整句换回标题 |
| 项目名 | 标题里写了仓库名，首句就得有 | 把名字弄进标题；标题自己没写仓库名时只提示 |
| 时长 | 首句 ≤ 10 秒（约 50 字） | 标题太长，回去删句头或砍形容词 |

比对时只挖掉 `[笑]` 这类气声标记和标点——**套话不挖**。上一版会挖掉「好家伙 / 神器 / 狠活 / 斩获 / Github / Stars」，那是给"复述"开的绿灯，现在关了：套话在标题里就是承重的，念出来才响。

改一个词（斩获→拿下）会打印"改了几处"、判过但提示；压字数、换语序、删半句，一律 ✗——这三种正是实际发生过的漂移方式。

`script` 和 `check` 都会自动跑这一项；`hook` 判 ✗ 时退出码是 2，别当噪音忽略。

## 八、交付前自检（机器判不了的）

- [ ] 首句和标题是不是**逐字一致**（只多一个 `[笑]`）——机检已判，别只信自己眼睛
- [ ] 标题念一遍顺不顺口，有没有 TTS 一定念错的词（Tauri → "套利奥"；改了词要连标题一起改）
- [ ] 首句念完多少秒（> 10 秒就砍标题，别砍首句）
- [ ] 标题前 15 字里有没有硬信息（数字 / 反常识），没有就调语序
- [ ] 第一段的画面能不能撑到这句话念完（撑不住会像卡了）
- [ ] 有没有空感叹词（太强了 / 绝了 / 无敌 / 炸裂）——标题里有就一起删，别指望念的时候跳过
- [ ] 封面大字、简介首句，和标题是不是同一个口径（核心数字 + 核心名词别各说各的）
- [ ] 简介的标签行写好没：5–8 个、`#GitHub` 和项目名都在、只用空格分隔（见 `SKILL.md` 3.5）
- [ ] 标题里每个数字和功能都能对着仓库验（不能验的就是造假，删掉重写）
- [ ] 标题里没写仓库名时，中段或片尾标版有没有出现一次（观众回搜靠它）

十条里有任何一条不过，**先改标题**，再看第一段——首句现在是标题的复印件，改首句没有意义。
